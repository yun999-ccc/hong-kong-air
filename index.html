一个具体的作业决策，三条清楚的边界

需求假设：主管在安排或调整接下来两小时的街道清洁任务时，希望先知道哪些测站值得复核。尚无真实作业流程或主管访谈证明这一需求。

01 / 已有信息

官方提供逐站当前 AQHI 和按站型发布的时段预报；网页直接展示这些原始信息。

02 / 项目增量

用历史数据检验趋势规则，提示未来两小时可能首次达到 AQHI 7+ 的测站，并公开命中、误报和漏报。

03 / 使用边界

提醒只触发人工复核。测站不代表具体街道，AQHI 7 也不是自动停工阈值。

INDUSTRY WORKFLOW

街道清洁主管的三步复核流程

这是待验证的工作流程设计，尚未经过真实作业单位试点。系统只提供复核提醒，不自动改变排班。

01 / 发现

识别前兆

班前或临时调整任务时，若测站 AQHI 为 6 且较前一小时上升，提示主管复核未来两小时的空气风险；先检查读数是否缺失或过期。

02 / 核对

结合任务地点

主管核对清洁任务地点、任务紧急程度、官方最新信息与站点代表性。邻近测站只能提供参考，不能当作街道级读数。

03 / 记录

人工决策

记录“继续／改时／再核对”及理由。AQHI 7 本身不等于停工建议；较高风险时应依据环保署户外雇员建议 ↗评估。真实效益仍需试点验证。

VIABILITY

可行性与尚待验证的假设

把数据证据、设计判断和商业假设分开，避免把原型写成已部署系统。

已核实

技术与数据

环保署提供逐站逐小时历史 AQHI；当前观测与站型预报可接入网页。正式在线预警仍需持续采集最近数小时数据、监控时效和部署服务。

待访谈

目标用户与市场

食环署公开资料 ↗证实香港有外判街道清洁服务。假设使用者是团队主管，购买方可能是承办商或采购单位；试点服务与后续年度服务仅是待验证的收费路径。当前没有购买意愿或市场规模证据。

待报价

成本与潜在收益

年成本需覆盖采集、存储、网页服务、通知与人工维护。可能的收益是减少人工复核时间或更早发现需核对的任务；两者均需试点记录和报价验证，不能从回测准确率直接推算。

须控制

风险与责任

重点控制漏报、误报、接口中断和测站代表性。过期或缺失时不出新的预警；主管保留最终决定权；不宣称已减少健康损害。

TECHNICAL PATH

技术链路与部署边界

已实现 · 历史验证

官方历史 CSV → 缺失与 * 标记处理 → 时间切分回测 → 规则对照与地图回放

待建设 · 在线应用

定时采集并保存近期数据 → 运行规则与时效校验 → 通知主管复核 → 保存处理记录

数据中断或超过时效阈值时，在线方案应停止发出新提醒；当前静态网页尚不具备在线逐站预警能力。

下一步要取得的行业证据

  1. 访谈：确认主管的任务安排流程、提醒接收方式和可接受误报量。
  2. 报价：取得采集服务、通知渠道及维护成本，明确潜在采购方。
  3. 试点：记录提醒后的人工复核、任务调整及耗时，才能比较实际效果。

READ THE MAP RIGHT

这张图如何解读

01

一个点，一处观测

AQHI 是监测站报告的短期健康风险指数。周围整个行政区并非同一读数。

02

先看站型

一般站反映日常环境，路边站适合观察繁忙道路附近的暴露情况，两类读数不应混为同一区域平均值。

03

留意发布时间

官方目标为逐小时更新。若来源中断或时间较旧，网页会清楚标示，避免把历史读数误看作实时结果。
